# LNL — релей Telegram

## Зачем

С телефона в РФ до Telegram часто плохо. Нужен **релей** на VPS с русским IP: телефон стучится **только** к нему, а сервер держит сессию Telegram.

## Роли

| Часть | Где | Задача |
|--------|-----|--------|
| **Клиент** | **отдельное Android-приложение** (`clients/android`) | UI: чаты, история, отправка. Только HTTP/WS к релею. Без MTProto / `api_id`. |
| **Релей** | Rust `lnl` на VPS | Одна или несколько изолированных сессий TG, REST + WS API. |
| **Debug UI** | `static/` (опционально) | Браузерная отладка API. **Не** продуктовый клиент. |

```text
┌──────────────────┐     HTTP + WS      ┌─────────────┐     MTProto      ┌──────────┐
│  Android (lnl)   │ ◄────────────────► │  lnl :8080  │ ◄──────────────► │ TG account A │
│  отдельный APK   │                    │  session A  │                  └──────────────┘
└──────────────────┘                    │  session B  │ ◄──────────────► ┌──────────────┐
                                        └─────────────┘                  │ TG account B │
                                                                         └──────────────┘
```

Контракт API: [API.md](./API.md).

## Сервер сейчас

- Независимые `Client`, история и WebSocket-шина для каждого Telegram-аккаунта
- Сид чатов из `TG_FOLDER`/`TG_SESSION_<ID>_FOLDER`; без рабочей папки —
  все реальные диалоги с ленивой загрузкой истории
- Scoped API `/api/sessions/{id}/…`; прежние URL работают через default-сессию
- Media-only сообщения, стикеры, фото, файлы, аудио, видео, голосовые и
  видеокружки проходят через ту же изолированную history/WS-шину
- Веб `static/` — только если нужен быстрый тест без APK

## Несколько Telegram-сессий

Без `TG_SESSIONS` релей запускается ровно как раньше: id `default`, файл
`./lnl.session`, папка `TG_FOLDER`.

```env
TG_SESSIONS=default,work
TG_DEFAULT_SESSION=default
TG_FOLDER=LNL
TG_SESSION_WORK_FOLDER=Support
```

ID — стабильный URL-safe slug из `a-z`, цифр и `_`, максимум 32 символа. Сессии
поднимаются в указанном порядке. `default` использует существующий `lnl.session`;
для остальных по умолчанию создаются `lnl.<id>.session`. Базовую папку задаёт
`TG_SESSION_DIR`, конкретный путь — `TG_SESSION_<ID>_FILE`.
Если `TG_DEFAULT_SESSION` не задан, выбирается id `default`, а без него — первый
id из `TG_SESSIONS`.

Без `TG_FOLDER` используется список всех Telegram-диалогов. Для него при
старте загружаются названия и последние сообщения, а последние 30 сообщений
конкретного чата — один раз при первом открытии. Если указанная папка удалена
или пуста, включается тот же fallback вместо пустого интерфейса.

В обычном terminal-режиме новые аккаунты по-прежнему авторизуются
последовательно. При `LNL_DEBUG_UI=1` публичный relay API стартует даже с
неавторизованными слотами, а phone → OTP → 2FA проходит в отдельной панели на
`LNL_ADMIN_BIND` (только loopback, Bearer token, same-origin mutations).
Каждый flow привязан к одному session id; challenge живёт в памяти не более
10 минут. Готовая сессия появляется в relay API только после сохранения файла,
`0600`, загрузки Telegram-профиля и диалогов.

Имя, username, маска телефона и raster-аватар доступны только защищённой
панели. Ferogram session-файл сохраняет Telegram-авторизацию между рестартами,
поэтому уже подключённый аккаунт пропускает OTP и сразу восстанавливает
профиль/диалоги.

Каждая сессия владеет своим клиентом, историей и broadcast-каналом. Неизвестный
scoped id возвращает `404`, настроенный, но не готовый — `503`; ни один из них
не подменяется default-сессией. При остановке релей закрывает API/WS,
останавливает update workers, сохраняет каждый session-файл и отключает все
клиенты.

Загрузка и скачивание бинарных вложений вынесены в
`/api/admin/sessions/{id}/…`: публичный Android listener эти маршруты не
монтирует. Admin middleware проверяет Bearer и exact Origin; upload дополнительно
ограничен 50 МиБ, одним файлом и одним параллельным transfer на сессию.
Временный файл создаётся с приватными правами и удаляется после Telegram
upload. Download заново получает сообщение, сверяет session/peer/message и
потоково отдаёт Telegram chunks, максимум три одновременных скачивания на
сессию и 100 МиБ на HTTP-ответ. Браузер получает медиа через authenticated
fetch и локальный Blob URL, поэтому токен не попадает в URL. Для OGG/Opus и
MP4/H.264 сервер сам проверяет длительность/кодек/размеры; клиентские подсказки
не используются.

`pin` изменяет текущий основной/архивный список Telegram через `pin_dialog`. Он намеренно
не переписывает `DialogFilter.pinned_peers`, чтобы не менять пользовательские
папки и существующую folder-бизнес-логику. Состояние основного списка и архива
восстанавливается при старте и обновляется по Telegram `DialogPinned`.

Session-файлы содержат Telegram-авторизацию. Основные файлы и служебные
`*.bak`/`*.tmp` исключены из Git. На Unix релей до первого write устанавливает
`umask 077`, а существующим файлам сразу выставляет `0600`, поэтому атомарные
перезаписи Ferogram остаются приватными. Case-варианты, symlink и hardlink
между настроенными файлами отклоняются до сети (hardlink — на Unix). Не
запускай два процесса с одним session-файлом: блокировка между процессами пока
не реализована.
